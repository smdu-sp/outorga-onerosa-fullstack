# 5. Perfis de Usuário e Permissões

O acesso ao Sistema de Controle de Outorga Onerosa será controlado por perfis de usuário, garantindo que cada área tenha acesso apenas às funcionalidades necessárias para execução de suas atividades.

Todos os usuários serão autenticados utilizando o sistema corporativo de autenticação da Prefeitura, e suas permissões serão definidas de acordo com o perfil associado.

---

# 5.1 Perfis de Usuário

O sistema possuirá os seguintes perfis de acesso:

- Técnico da Coordenadoria de Análise
- Coordenadoria de Atendimento ao Público (CAP)
- DEUSO
- FUNDURB
- Gabinete (GAB)
- Administrador do Sistema

---

# 5.2 Técnico da Coordenadoria de Análise

São considerados Técnicos da Coordenadoria de Análise os usuários pertencentes às seguintes coordenadorias:

- RESID
- SERVIN
- COMIN
- CAEPP
- PARHIS

## Permissões

O Técnico poderá:

- Criar novos processos;
- Consultar processos da sua coordenadoria;
- Visualizar informações obtidas pelas integrações;
- Visualizar a memória de cálculo;
- Validar o cálculo;
- Solicitar novo cálculo quando necessário;
- Encaminhar processos para a CAP;
- Consultar o histórico do processo.

O Técnico **não poderá**:

- Alterar informações do cálculo;
- Alterar dados obtidos das integrações;
- Cadastrar parcelas;
- Registrar pagamentos;
- Alterar processos após o envio para a CAP.

---

# 5.3 Coordenadoria de Atendimento ao Público (CAP)

A CAP será responsável pelo gerenciamento financeiro da Outorga Onerosa.

## Permissões

A CAP poderá:

- Visualizar processos encaminhados para sua etapa;
- Cadastrar o parcelamento;
- Alterar o plano de parcelamento;
- Registrar pagamentos;
- Registrar pagamentos antecipados;
- Registrar quitação total;
- Consultar histórico do processo.

A CAP **não poderá**:

- Alterar o cálculo;
- Alterar informações técnicas;
- Solicitar novo cálculo;
- Excluir processos.

---

# 5.4 DEUSO

A DEUSO será responsável pelo acompanhamento dos processos quitados.

## Permissões

A DEUSO poderá:

- Consultar processos quitados;
- Consultar pagamentos;
- Consultar histórico;
- Acompanhar processos;
- Emitir relatórios.

A DEUSO **não poderá**:

- Alterar informações do processo;
- Alterar parcelamentos;
- Registrar pagamentos;
- Alterar cálculos.

---

# 5.5 FUNDURB

O perfil FUNDURB terá acesso exclusivamente para consulta das informações do sistema.

## Permissões

O FUNDURB poderá:

- Consultar todos os processos;
- Consultar pagamentos;
- Consultar parcelamentos;
- Consultar memória de cálculo;
- Visualizar dashboards;
- Emitir relatórios.

O FUNDURB **não poderá** realizar qualquer alteração nos dados do sistema.

---

# 5.6 Gabinete (GAB)

O perfil Gabinete possuirá acesso gerencial às informações do sistema.

## Permissões

O Gabinete poderá:

- Consultar todos os processos;
- Consultar indicadores;
- Visualizar dashboards;
- Emitir relatórios.

O Gabinete **não poderá** alterar informações do sistema.

---

# 5.7 Administrador do Sistema

O Administrador será responsável pela administração da aplicação.

## Permissões

O Administrador poderá:

- Gerenciar usuários;
- Gerenciar perfis de acesso;
- Gerenciar permissões;
- Parametrizar o sistema;
- Consultar logs;
- Consultar todas as informações;
- Executar rotinas administrativas.

---

# 5.8 Restrições de Acesso

O sistema deverá restringir automaticamente as funcionalidades disponíveis de acordo com o perfil do usuário.

Além das permissões por perfil, poderão existir restrições baseadas na coordenadoria do usuário, impedindo o acesso a processos de outras unidades quando aplicável.

# 5.10 Considerações

O sistema deverá utilizar um modelo de autorização baseado em papéis (Role-Based Access Control - RBAC), permitindo que novas permissões e perfis possam ser adicionados futuramente sem necessidade de alterações estruturais na aplicação.

Toda ação executada por um usuário deverá ser registrada em log de auditoria, contendo identificação do usuário, data, horário e operação realizada.
