# 8. Integrações com Sistemas Externos

O Sistema de Controle de Outorga Onerosa depende da integração com sistemas corporativos da Prefeitura de São Paulo para obtenção das informações necessárias ao gerenciamento dos processos.

As integrações serão responsáveis pelo preenchimento automático das informações do processo, reduzindo o preenchimento manual e garantindo consistência entre os sistemas.

O Controle de Outorga atuará como consumidor dessas informações, armazenando os dados necessários para execução do fluxo administrativo e auditoria.

---

# 8.1 Arquitetura das Integrações

O fluxo de integração ocorrerá conforme o diagrama abaixo:

```text
Técnico informa o Processo SEI
              │
              ▼
      Sistema de Controle
              │
              ├──────────────┐
              ▼              ▼
    Sistema de Processos   Sistema de Cálculo
              │              │
              └──────┬───────┘
                     ▼
                 GeoSampa
                     │
                     ▼
      Consolidação das Informações
                     │
                     ▼
         Processo disponível para análise
```

---

# 8.2 Sistema de Processos Administrativos

## Objetivo

Obter automaticamente as informações cadastrais do processo administrativo.

## Dados esperados

Exemplos de informações que poderão ser obtidas:

- Número do processo;
- Tipo de processo;
- Interessado;
- Responsável;
- Situação do processo;
- Data de abertura;
- Unidade responsável;
- Endereço do imóvel;
- SQL do imóvel;
- Demais informações disponíveis.

A definição completa dos campos dependerá da documentação da API.

---

# 8.3 GeoSampa

## Objetivo

Obter automaticamente as informações territoriais do imóvel.

## Dados esperados

Exemplos:

- Distrito;
- Subprefeitura;
- Zoneamento;
- Macroárea;
- Macrozona;
- Operação Urbana;
- ZEIS;
- Melhoramentos públicos;
- Dados cartográficos;
- Outras informações urbanísticas necessárias ao processo.

A definição completa dependerá da documentação da API.

---

# 8.4 Sistema de Cálculo da Outorga Onerosa

## Objetivo

Obter automaticamente o cálculo oficial da Outorga Onerosa.

O Sistema de Controle não realizará qualquer cálculo internamente.

## Dados esperados

O sistema deverá receber, no mínimo:

- Valor da Outorga;
- Memória de cálculo;
- Áreas utilizadas;
- Fatores aplicados;
- Parâmetros utilizados;
- Dados necessários para composição da planilha de cálculo;
- Demais informações retornadas pela API.

Essas informações serão utilizadas para instrução do processo administrativo.

---

# 8.5 Persistência das Informações

As informações recebidas por meio das integrações deverão ser armazenadas juntamente ao processo.

Essa persistência tem como objetivo:

- garantir rastreabilidade;
- preservar os dados utilizados durante a análise;
- permitir auditoria;
- evitar dependência contínua dos sistemas externos.

---

# 8.6 Tratamento de Falhas

Caso alguma integração não retorne as informações esperadas, o sistema deverá:

- informar o erro ao usuário;
- identificar qual integração apresentou falha;
- registrar a ocorrência em log;
- permitir nova tentativa de consulta.

O processo somente poderá prosseguir quando todas as informações obrigatórias estiverem disponíveis.

---

# 8.7 Evolução das Integrações

O sistema deverá permitir a inclusão de novas integrações futuramente, sem impacto significativo na arquitetura da aplicação.

Novas APIs poderão ser incorporadas conforme necessidade da SMUL.
